# Roadmap: reliable agent handoff from delivery to completion

## Verified progress — 2026-10-17

- Phase 0 complete: JSON doctor separates persistence, receipt, acceptance,
  execution, hook identities, worker health and failover activation.
- Phase 1 operational for the supervised read-only Codex worker. A synthetic
  `claude-code → codex` task completed without a follow-up human prompt; the
  real Ada-client proof is still pending after her provider limit clears.
- Phase 2 partial: safe activation baselines, accepted-task protection, typed
  Codex provider state, evidence-labelled Claude CLI detection, and durable
  both-limited queues are implemented. A supervised Claude worker and the real
  two-direction host test remain open.
- Phase 4 partial: the room now distinguishes offline, provider-unknown and
  provider-limited states and shows a bounded reason. Claim blockers and
  next-eligible task time remain open.
- Last full local regression: 291 tests passed on Linux/WSL. This is not yet the
  required Windows 11 restart/logon matrix from Phase 5.

## Primary goal

An authorised task sent between Ada (Claude Code) and Nox (Codex) is durably
stored, picked up without a human prompt, processed exactly once as far as the
provider permits, and returned with an auditable result. When that cannot
happen, the room says whether the failure is delivery, wake-up, worker health,
provider quota, lease conflict, or human review.

## Phase 0 — Diagnostic truth

**How this serves the primary goal:** It makes every later fix measurable and
prevents a stored message from being misreported as a successfully woken agent.

### What to implement

- Extend `agent-lease doctor` with a machine-readable `--json` report and
  separate checks for identity, filesystem/SQLite, MCP configuration, lifecycle
  hooks, wake support, broker reachability, worker observation, fallback setup,
  and the recipient's queue states.
- Report delivery layers independently: persisted, seen by a lifecycle hook,
  explicitly accepted, leased/started, and terminal.
- Detect the locally installed Codex `queue` command as a supported capability,
  but do not claim that a named session is reachable until a live probe proves
  it.

### Documentation references

- Installed CLI contracts: `codex queue --help`, `codex app-server daemon
  version`, and `codex agents --help` from Codex CLI 0.162.1 / app-server 0.163.0.
- Existing lifecycle path: `src/agent_lease_mcp/lifecycle.py`,
  `src/agent_lease_mcp/store.py`, and `docs/ZPRAVY-A-POTVRZENI.md`.
- Existing deployment checks: `src/agent_lease_mcp/doctor.py` and
  `src/agent_lease_mcp/init_cmd.py`.

### Verification checklist

- JSON output parses without scraping human text and contains no message body,
  lease token, web token, or provider credential.
- A persisted-but-unseen task, a seen-but-unaccepted task, and an
  accepted-but-not-started task produce different counts.
- Human output remains backward compatible.
- The clean test suite passes on Python 3.11–3.13; socket tests are also run
  outside sandboxes that forbid local sockets.

### Anti-pattern guards

- Do not infer wake-up from a touched signal file or configured hook.
- Do not treat `accept` as task completion or a lifecycle receipt as execution.
- Do not expose message text or capability tokens in diagnostics.

## Phase 1 — Always-on Codex intake

**How this serves the primary goal:** It gives authorised Codex tasks a real
consumer when no human is typing in an interactive session.

### What to implement

- First productionise the existing `Bridge.step` state machine as the bounded,
  read-only worker: lease, mark seen, accept, persist `started`, run, persist a
  result, then move to a terminal state.
- Install and supervise the broker and Codex worker for the WSL user, with a
  durable worker heartbeat and an explicit offline reason.
- Add a Codex adapter for the supported shared app-server: start/resume a
  bridge-owned thread and use `turn/start` for idle work. Use `codex queue` only
  for an explicitly configured existing session. Use `turn/steer` only for a
  related turn that is already active.
- Persist provider thread/turn identifiers around dispatch so a crash can be
  reconciled instead of blindly repeated.

### Documentation references

- Copy the task transition order from `src/agent_lease_mcp/bridge.py:153`.
- Copy service hardening from `deploy/systemd/agent-lease-bridge@.service` and
  `deploy/systemd/agent-lease-broker.service`.
- Follow the installed Codex CLI contracts above and the app-server protocol
  schema generated by `codex app-server generate-json-schema`; do not invent RPC
  methods.

### Verification checklist

- Ada sends an authorised task while no human prompts Codex; it reaches
  `accepted`, `started`, a terminal state, and a reply.
- Killing the worker before `started` permits one safe retry; killing it after
  `started` yields `needs_review`, never a blind duplicate.
- Restarting the broker/worker preserves the queue and reconciles the provider
  turn identifier.

### Anti-pattern guards

- Do not write into arbitrary TUI stdin or private sockets.
- Do not attach an autonomous worker to a human-owned interactive thread.
- Do not use `--dangerously-bypass-approvals-and-sandbox`.

## Phase 2 — Bidirectional intake and provider-state failover

**How this serves the primary goal:** It makes both directions reliable and
keeps work safe when either provider is temporarily unavailable.

### What to implement

- Add the same supervised worker contract for Claude Code using only a
  currently supported headless/session interface verified on the installed
  client.
- Store typed availability observations: state, source, observed time, reset
  time, and reason. Accept explicit user/agent reports and documented provider
  events; retain regex parsing only as labelled heuristic evidence.
- Bound failover with handover lineage and a maximum hop count. Transfer only
  genuinely unstarted tasks; an accepted task must either own a task lease or
  remain visibly `accepted_without_lease` for repair.
- On reset, restore availability without moving already handed-off work back.

### Documentation references

- Existing limits/failover behavior: `docs/LIMITY-A-FAILOVER.md` and
  `Store.failover_sweep` in `src/agent_lease_mcp/store.py`.
- Existing provider-error handling: `_RATE_LIMIT`, `parse_retry_after`, and
  `Bridge.step` in `src/agent_lease_mcp/bridge.py`.

### Verification checklist

- Ada→Nox and Nox→Ada both complete without a follow-up human prompt.
- Explicit and provider-reported limits are distinguishable from offline state.
- Both-limited leaves one durable pending delivery; reset causes no duplicate.
- A cyclic fallback configuration stops after the configured bound.

### Anti-pattern guards

- Do not fabricate a limit reset time when the client provides none.
- Do not move `leased`, `started`, or `needs_review` work.
- Do not equate a stale heartbeat with a provider quota error.

## Phase 3 — Lease-aware scheduling and queue policy

**How this serves the primary goal:** It lets an available agent do independent
work instead of waiting behind a task whose files are currently leased.

### What to implement

- Add declared task worksets (paths), dependencies, priority, and handover
  lineage to the durable task schema.
- Select the highest-priority eligible task with stable FIFO ordering; skip a
  task whose workset conflicts with live path claims and preserve it in place.
- Add bounded retries/backoff, dedupe requirements for automatic senders, queue
  limits, and explicit dead-letter/review transitions.
- Keep path-claim TTL, renewal, ownership checks, and atomic edit gating as the
  enforcement boundary.

### Documentation references

- Reuse `covers`, `_conflicts`, `Store.claim`, `Store.edit_gate`,
  `Store.lease_next`, and `Store.extend_lease`.
- Reuse the current delivery state machine in `src/agent_lease_mcp/models.py`.

### Verification checklist

- A blocked first task is skipped for an independent second task without being
  cancelled or reordered permanently.
- Two workers cannot lease the same task or edit the same covered path.
- Lease renewal, explicit release, crash expiry, and `needs_review` recovery are
  covered by concurrent regression tests.

### Anti-pattern guards

- Do not guess a task's files from free-form text.
- Do not release another agent's claim or retry started work automatically.
- Do not implement priority by destructively rewriting message order.

## Phase 4 — Explainable room and operational safety

**How this serves the primary goal:** A human can see why work is moving or
stalled and can intervene without inspecting SQLite or process lists.

### What to implement

- Extend the room board with broker/worker health, transport, provider-state
  source/time, blocking claim, next eligible time, last error, and a stable
  offline-reason enum.
- Preserve output escaping, token isolation, origin checks, session cookies,
  stream limits, and redaction for every new field.
- Add audit events for dispatch intent, provider acceptance, reconciliation,
  failover hops, and human intervention without storing hidden reasoning.

### Documentation references

- Reuse `Store.board` and the escaped renderers in
  `src/agent_lease_mcp/webui.py`.
- Reuse the boundaries in `docs/security-inventory.md` and the verified fixes
  in `docs/security-findings.md`.

### Verification checklist

- The board distinguishes offline worker, missing hook, broker down, unknown
  provider state, explicit limit, blocked lease, and human review.
- Adversarial strings in every new field remain text, not markup.
- Snapshots and SSE never contain lease, web-session, or provider tokens.

### Anti-pattern guards

- Do not derive causal labels only from free-form status text.
- Do not display raw provider/tool output or internal model reasoning.
- Do not make the browser token available to JavaScript after session exchange.

## Phase 5 — Real-host verification, documentation, and skill

**How this serves the primary goal:** It proves the promises on the actual
Windows 11 + WSL clients and makes the supported setup reproducible.

### What to implement

- Run a real-client matrix covering interactive hooks, supervised workers,
  direct SQLite/broker transports, provider limits, crashes, WSL shutdown, and
  Windows logon startup.
- Reconcile `README`, `TODO`, `CHANGELOG`, Czech docs, security inventory, and
  troubleshooting with only empirically verified capabilities.
- After all release gates pass, create the Agensi installation/configuration
  skill with version checks, reversible setup, doctor verification, and clear
  capability limits.

### Documentation references

- Start from `deploy/windows/start-bridge.ps1`, `deploy/systemd/`,
  `.github/workflows/ci.yml`, and the current release documents.
- Use the real installed client `--help` output and official vendor docs for
  every integration contract.

### Verification checklist

- The no-human Ada→Nox and Nox→Ada tests pass on Windows 11 + WSL after login,
  after a worker crash, and after a WSL restart.
- All unit/integration/security tests pass, and documentation claims match the
  measured matrix.
- The skill installs into a clean profile, is reversible, and leaves no secret
  in source, logs, command history, or generated reports.

### Anti-pattern guards

- Do not call Linux-only simulation a Windows verification.
- Do not publish a wake/limit guarantee based only on configuration presence.
- Do not ship the skill before the deployment and recovery matrix is green.
